## 最新配置方式

OpenCode 和 WorkBuddy 都有桌面端，也提供官方自带的免费 AI。第一次使用时，先打开桌面端并选择一个免费 AI，确认客户端能正常工作，再决定是否接入 Xcompute。

需要更强模型、长上下文、多文件任务或统一 API 时，再配置 Xcompute：

| 配置项 | 内容 |
| --- | --- |
| Base URL | `https://xcompute.us/v1` |
| API Key | 在 [Xcompute 控制台](https://xcompute.us/keys)创建 |
| 模型列表 | 请求 `GET https://xcompute.us/v1/models` 自动获取 |
| 上下文 | 当前对外提供的模型均按 1M 上下文使用 |

客户端支持 OpenAI 兼容接口时，通常只需要填写 Base URL 和 API Key，然后点击“获取模型”“同步模型”或“刷新模型列表”。不要手工把模型名一条条写进配置文件。

## 用免费 AI 自动配置

在客户端自带的免费 AI 对话框中，可以直接发送下面的指令。执行配置前，先确认客户端展示的配置内容，不要让 AI 读取或输出已有密钥。

```text
请帮我添加一个 OpenAI 兼容的模型提供商，名称为 Xcompute。
Base URL 使用 https://xcompute.us/v1。
请通过 GET /models 自动读取可用模型，不要手工猜测或固定模型名。
上下文长度按 1M 配置；API Key 由我在客户端的密钥输入框中填写，不要在对话中显示或保存密钥。
配置完成后先列出将要使用的模型和请求地址，等待我确认后再保存。
```

## 手动配置字段

如果客户端不支持自动配置，填写以下字段：

| 字段 | 值 |
| --- | --- |
| Provider / 供应商名称 | `Xcompute` |
| Protocol / 协议 | `OpenAI Compatible` |
| Base URL | `https://xcompute.us/v1` |
| API Key | 你的 Xcompute API Key |
| Models | 从 `GET /v1/models` 获取 |
| Context length | `1000000` |

验证模型列表：

```bash
curl https://xcompute.us/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

模型列表以接口实际返回为准。模型可能受到账号分组、渠道状态和权限影响。

## 选择免费 AI 还是 Xcompute

- 简单问答、摘要、代码解释和小修改：优先使用客户端自带免费 AI。
- 长文档、多文件重构、复杂推理和指定模型：使用 Xcompute。
- 不要为了简单任务默认使用最高规格模型。
- 先让 AI 给计划，再执行修改；只提供完成任务所需的文件和上下文。
- 减少重复发送历史内容，完成一步就检查结果，可以直接降低 Token 消耗。

## 支持的客户端

- [OpenCode 桌面端](/opencode-install)：代码项目和 Agent 任务。
- [WorkBuddy 桌面端](/workbuddy-client)：日常文档、表格和资料任务。
- [Codex](/codex-cli-app)：官方订阅或 OpenAI 兼容配置，取决于当前版本支持的 Provider。
- [Claude Code](/claude-code)：官方账号或当前版本支持的兼容 Provider。
- [龙虾](/lobster)：使用客户端内置配置或 OpenAI 兼容 Provider。
- [Hermes](/hermes)：使用客户端内置配置或 OpenAI 兼容 Provider。
